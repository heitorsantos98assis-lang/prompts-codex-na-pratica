# Prompt 10 — DOCS
## Gerar documentação do sistema em segundos

**Quando usar:** Para documentar o projeto para o time, para você mesmo ou para um dev que entrar depois.

---

## Prompt — Documentação técnica (copie e cole no Codex)

```
Preciso documentar o sistema [NOME DO SISTEMA] para que qualquer pessoa consiga entender e dar manutenção.

Para quem é esta documentação:
[ex: para um desenvolvedor que vai entrar no projeto / para o meu time que não é dev / para mim mesmo no futuro]

O que precisa estar documentado:
- [ex: como rodar o projeto localmente]
- [ex: todas as rotas da API com exemplos de request e response]
- [ex: como o sistema de autenticação funciona]
- [ex: como fazer deploy de uma atualização]

Por favor:
1. Leia os arquivos do projeto para entender o que existe
2. Gere um README.md completo na raiz do projeto
3. Documente todas as rotas da API em um arquivo separado (API.md)
4. Crie um guia de onboarding para quem for mexer no projeto pela primeira vez
5. Escreva em linguagem clara — sem jargão técnico desnecessário
```

---

## Prompt — Documentar uma funcionalidade específica

```
Preciso documentar como funciona [NOME DA FUNCIONALIDADE, ex: o sistema de permissões].

Crie uma explicação que responda:
1. O que essa funcionalidade faz e por que existe
2. Como ativar / configurar
3. Como usar no dia a dia
4. O que fazer se algo der errado

O público que vai ler: [ex: meu sócio que não é dev / time de suporte / futuro desenvolvedor]
```

---

## Dicas

- Documente enquanto está construindo — não deixe para o final
- Uma boa documentação economiza horas de explicação depois
- Atualize o README toda vez que fizer uma mudança significativa no sistema
